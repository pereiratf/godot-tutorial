Módulo 06 · Aula 6.1

Menu principal e pause

Dar ao jogo uma porta de entrada e um botão de respiro: a tela que abre antes do nível e o menu que congela a ação sem sair dela.

~30 minutos C# + UI

O jogo não começa no nível

Até o Módulo 05 o jogo abria direto no mapa_1. Mas todo jogo de verdade tem uma porta de entrada: uma tela de título onde o jogador escolhe começar, ver opções ou sair. Essa tela é só mais uma cena — feita de nodes Control, como o HUD do Módulo 05 — e o jogo passa a abrir por ela.

Definir qual cena abre é uma configuração: Project Settings → Application → Run → Main Scene. Trocar o mapa_1 pela MainMenu ali já muda a porta de entrada do jogo.

Fluxo de telas do jogo
▶
MainMenu
Abre primeiro. Botões Jogar / Opções / Sair.
↓
mapa_1 (jogo)
"Jogar" troca para a cena do nível com ChangeSceneToFile.
⏸
PauseMenu
Sobre o jogo, sem trocar de cena — congela e mostra Continuar / Sair.

O menu principal

A MainMenu é um Control com botões. Cada Button tem o signal pressed, que você conecta a um método — exatamente como fez com o botão de "Tentar de novo" no Módulo 05.

MainMenu.cs C# 
using Godot;

public partial class MainMenu : Control
{
    // Conectado ao "pressed" do botão Jogar
    private void OnPlayPressed()
    {
        GetTree().ChangeSceneToFile("res://Scenes/World/mapa_1.tscn");
    }

    // Conectado ao "pressed" do botão Sair
    private void OnQuitPressed()
    {
        GetTree().Quit(); // fecha o jogo
    }
}

Pause: congelar sem sair da cena

O pause é diferente de trocar de cena: você quer parar o jogo no lugar e mostrar um menu por cima, mantendo o nível intacto atrás. O Godot congela toda a árvore com uma única propriedade: GetTree().Paused.

O paradoxo do menu congelado

Se Paused = true congela tudo, como o próprio menu de pause continua respondendo aos cliques? A resposta é o Process Mode do node. Ajuste o PauseMenu para Process Mode = Always no Inspector — assim ele ignora o congelamento e segue processando input, enquanto o jogo (em Inherit) para.

Process Mode e o pause
Inherit (padrão)
Player, inimigos, mundo — congelam quando Paused = true.
Always
O PauseMenu — continua vivo durante o pause para receber os cliques.
PauseMenu.cs C# 
using Godot;

public partial class PauseMenu : CanvasLayer
{
    public override void _Ready() => Visible = false;

    public override void _UnhandledInput(InputEvent @event)
    {
        if (@event.IsActionPressed("pause")) Toggle();
    }

    private void Toggle()
    {
        bool paused = !GetTree().Paused;
        GetTree().Paused = paused; // congela / descongela o jogo
        Visible = paused;              // mostra / esconde o menu
    }

    // Botão Continuar
    private void OnResumePressed() => Toggle();

    // Botão Sair para o menu
    private void OnQuitToMenuPressed()
    {
        GetTree().Paused = false; // SEMPRE despause antes de trocar de cena
        GetTree().ChangeSceneToFile("res://Scenes/UI/MainMenu.tscn");
    }
}
Despause antes de sair

Se você trocar de cena com o jogo ainda pausado, a próxima cena nasce congelada — o clássico "abri o jogo e nada se move". Sempre zere Paused antes de um ChangeSceneToFile.

Criar o menu e o pause

Vamos dar ao jogo uma tela de título e um menu de pause funcional.

Projeto base deste módulo

Continue do projeto do Módulo 05 (com HUD, GameManager e game over). A arte de título está em res://Assets/environment/ (o title-screen do Sunny Land).

1
Crie a ação de pause

Em Project Settings → Input Map, crie a ação pause e associe a tecla Esc (e, se quiser, o botão Start do gamepad).

2
Monte a MainMenu

Nova cena com Control como raiz (MainMenu). Adicione um título e três Button: Jogar, Opções, Sair. Use um VBoxContainer para empilhá-los. Salve em res://Scenes/UI/MainMenu.tscn.

3
Ligue os botões e defina a Main Scene

Anexe MainMenu.cs, conecte os pressed de Jogar e Sair. Em Project Settings → Application → Run → Main Scene, aponte para MainMenu.tscn. (O botão Opções fica para a Aula 6.2.)

4
Monte o PauseMenu

Nova cena com CanvasLayer como raiz (PauseMenu), com um painel e dois Button: Continuar e Sair para o menu. No Inspector da raiz, defina Process Mode = Always. Salve em res://Scenes/UI/PauseMenu.tscn.

5
Instancie o pause no nível

No mapa_1.tscn, instancie PauseMenu.tscn. Anexe PauseMenu.cs, conecte os botões e confirme que ele inicia invisível.

6
Teste o fluxo completo

Rode. O jogo deve abrir na MainMenu; "Jogar" leva ao nível; Esc congela e mostra o pause; "Continuar" volta ao jogo; "Sair para o menu" retorna à tela de título — sem ficar congelado.

O menu de pause também congelou?

Se o pause aparecer mas os botões não responderem, quase sempre o Process Mode do PauseMenu ficou em Inherit. Mude para Always na raiz da cena do menu.

Botão "Continuar" que aparece condicionalmente Aula 6.1 · Estado e UI
Médio

No menu principal, o botão "Continuar" (retomar um jogo salvo) só faz sentido se existir um save. Faça-o aparecer condicionalmente — deixando o gancho pronto para o save/load da Aula 6.2.

  • 1
    Adicione um botão "Continuar" na MainMenu, acima de "Jogar"
  • 2
    No _Ready, verifique se existe um arquivo de save (por ora, FileAccess.FileExists("user://savegame.cfg"))
  • 3
    Defina Visible do botão conforme o resultado — sem save, ele nem aparece
  • 4
    Ligue "Continuar" para carregar o nível (por enquanto, o mesmo ChangeSceneToFile do Jogar)
  • 5
    Teste criando um arquivo vazio em user:// e confirme que o botão aparece só quando ele existe

A pasta user:// é o diretório de dados do jogo (você vai conhecê-la a fundo na 6.2). FileAccess.FileExists("user://savegame.cfg") devolve true/false sem abrir o arquivo.

Esconder um botão é só botao.Visible = false. Como está num VBoxContainer, os outros sobem para ocupar o espaço automaticamente.

Opções e save/load

Deixar o jogador ajustar o jogo e guardar o que importa entre sessões — configurações e progresso que sobrevivem a fechar o programa.

~35 minutos C# + persistência

Onde os dados sobrevivem: user://

Quando o jogo fecha, tudo na memória some. Para guardar volume, tela cheia ou o recorde, você precisa escrever em disco. Mas onde? Não em res:// — essa pasta é só leitura no jogo exportado (vira o .pck). O lugar certo é user://: uma pasta de dados por-usuário que o Godot mapeia para cada sistema (AppData no Windows, ~/.local/share no Linux, etc.).

res:// é o livro; user:// é o caderno

O res:// é o conteúdo impresso do jogo — você lê, mas não rabisca. O user:// é o seu caderno pessoal ao lado: é onde o jogo anota o que você mudou. Cada jogador tem o seu.

ConfigFile: um formato simples de chave-valor

Você poderia inventar um formato de texto, mas o Godot já traz o ConfigFile: um arquivo estilo .ini organizado em seções e chaves. Perfeito para configurações e saves pequenos, sem depender de JSON à mão.

Separe settings de savegame

Configurações (volume, tela) e progresso (recorde, fase) são coisas diferentes, com ciclos de vida diferentes. Use dois arquivos: user://settings.cfg e user://savegame.cfg. Apagar o save não deve zerar o volume.

Aplicar configurações de verdade

Salvar um número não muda nada sozinho — você precisa aplicar o valor ao sistema certo. Volume vai para o AudioServer; tela cheia vai para o DisplayServer.

Options.cs — aplicar e salvar C# 
using Godot;

public partial class Options : Control
{
    private const string Path = "user://settings.cfg";

    // Signal "value_changed" do HSlider de volume (0..1)
    private void OnMasterVolumeChanged(double value)
    {
        int bus = AudioServer.GetBusIndex("Master");
        AudioServer.SetBusVolumeDb(bus, Mathf.LinearToDb((float)value));
        Save();
    }

    // Signal "toggled" do CheckButton de tela cheia
    private void OnFullscreenToggled(bool on)
    {
        DisplayServer.WindowSetMode(on
            ? DisplayServer.WindowMode.Fullscreen
            : DisplayServer.WindowMode.Windowed);
        Save();
    }

    private void Save()
    {
        var cfg = new ConfigFile();
        int bus = AudioServer.GetBusIndex("Master");
        cfg.SetValue("audio", "master_db", AudioServer.GetBusVolumeDb(bus));
        cfg.SetValue("video", "fullscreen",
            DisplayServer.WindowGetMode() == DisplayServer.WindowMode.Fullscreen);
        cfg.Save(Path);
    }
}

Carregar no boot: um autoload de Settings

As configurações precisam ser aplicadas assim que o jogo abre, antes de qualquer tela. O lugar natural é um autoload (como o GameManager do Módulo 05) que, no _Ready, lê o arquivo e aplica os valores.

Settings.cs — autoload, carrega no início C# 
public override void _Ready()
{
    var cfg = new ConfigFile();
    if (cfg.Load("user://settings.cfg") != Error.Ok)
        return; // primeira vez: sem arquivo, usa os padrões

    int bus = AudioServer.GetBusIndex("Master");
    AudioServer.SetBusVolumeDb(bus, (float)cfg.GetValue("audio", "master_db", 0f));

    bool fs = (bool)cfg.GetValue("video", "fullscreen", false);
    DisplayServer.WindowSetMode(fs
        ? DisplayServer.WindowMode.Fullscreen
        : DisplayServer.WindowMode.Windowed);
}
Save do jogo é o mesmo padrão

Guardar o recorde é o mesmo ConfigFile, em user://savegame.cfg: no GameManager, ao bater um recorde, faça cfg.SetValue("progress", "high_score", HighScore) e cfg.Save(...). Carregue no _Ready do GameManager para o HUD já mostrar o melhor placar.

Menu de opções com persistência

Vamos construir a tela de Opções (volume + tela cheia), salvar em user:// e aplicar tudo no boot.

1
Monte a cena de Opções

Nova cena Control (Options) com um HSlider de volume, um CheckButton de tela cheia e um botão Voltar. Salve em res://Scenes/UI/Options.tscn e ligue o botão Opções do menu principal a ela.

2
Aplique volume e tela cheia

Anexe Options.cs. Conecte o value_changed do slider a OnMasterVolumeChanged e o toggled do checkbutton a OnFullscreenToggled (código da aba Conteúdo).

3
Salve em user://

Confirme que cada mudança chama Save() e grava em user://settings.cfg. Para inspecionar o arquivo, use Editor → Open User Data Folder.

4
Crie o autoload Settings

Crie Settings.cs (carrega e aplica no _Ready) e registre em Project Settings → Autoload. Ele deve rodar antes de qualquer tela.

5
Salve o recorde

No GameManager, ao fim de uma partida, se Score superar o recorde, grave em user://savegame.cfg. Carregue no _Ready para o HUD exibir o melhor placar.

6
Teste a persistência

Ajuste o volume, ligue tela cheia, feche o jogo e abra de novo: as configurações devem voltar aplicadas. Bata um recorde, feche e reabra: o recorde continua lá.

Ponto de verificação

Persistência funciona quando: (1) mudar o volume/tela grava em settings.cfg, (2) reabrir o jogo aplica os valores salvos, (3) o recorde sobrevive em savegame.cfg separado das configurações.

Sliders separados de Música e SFX Aula 6.2 · Audio buses
Médio

Um único volume mestre é grosseiro — jogadores querem baixar a música e manter os efeitos. Crie buses de áudio separados e um slider para cada.

  • 1
    No painel Audio (parte de baixo do editor), crie os buses Music e SFX, ambos roteados para Master
  • 2
    Configure a música para tocar no bus Music e os efeitos no SFX (propriedade Bus do AudioStreamPlayer)
  • 3
    Adicione dois sliders nas Opções e aplique cada um ao bus correspondente com SetBusVolumeDb
  • 4
    Salve e carregue os três volumes (Master, Music, SFX) no settings.cfg
  • 5
    Teste: baixar só a música deve deixar os efeitos intactos

Cada bus tem um índice (AudioServer.GetBusIndex("Music")). O código do volume mestre serve igual para qualquer bus — só muda o nome.

Sliders trabalham em escala linear (0..1), mas o áudio é em decibéis. Sempre converta com Mathf.LinearToDb ao aplicar e Mathf.DbToLinear ao carregar de volta para o slider.

Transições e remapeamento

Dois toques de polimento: um fade suave entre telas e a possibilidade de o jogador reconfigurar os controles do próprio jeito.

~30 minutos C# + polimento

Por que o corte seco incomoda

No Módulo 05 as trocas de cena eram instantâneas: num frame você está no jogo, no outro no game over. Funciona, mas é abrupto. Um fade — escurecer, trocar, clarear — dá respiro e esconde o pequeno engasgo de carregar a cena. É barato e eleva muito a percepção de acabamento.

Um overlay de transição que sobrevive à troca

O truque: a troca de cena destrói a cena atual, então o fade não pode viver nela. Ele mora num autoload com um CanvasLayer e um ColorRect preto por cima de tudo. Como autoload, ele persiste entre cenas e pode escurecer antes de trocar e clarear depois.

Anatomia da transição
1
Fade to black
Anima o alpha do ColorRect de 0 → 1 com um Tween.
2
ChangeSceneToFile
Com a tela preta, a troca acontece escondida.
3
Fade from black
Anima o alpha de 1 → 0, revelando a nova cena.
SceneTransition.cs — autoload C# 
using Godot;
using System.Threading.Tasks;

public partial class SceneTransition : CanvasLayer
{
    private ColorRect _fade;

    public override void _Ready()
    {
        _fade = GetNode<ColorRect>("Fade");
        _fade.Modulate = new Color(1, 1, 1, 0); // começa transparente
    }

    public async void ChangeScene(string path)
    {
        await FadeTo(1f);                 // escurece
        GetTree().ChangeSceneToFile(path);  // troca escondido
        await FadeTo(0f);                 // clareia
    }

    private async Task FadeTo(float alpha)
    {
        Tween tween = CreateTween();
        tween.TweenProperty(_fade, "modulate:a", alpha, 0.3f);
        await ToSignal(tween, Tween.SignalName.Finished);
    }
}

Com isso, trocar de cena vira SceneTransition.Instance.ChangeScene("res://...") em vez do GetTree().ChangeSceneToFile direto — e todo o jogo ganha fade de graça.

O overlay precisa bloquear... ou não

Ponha o ColorRect cobrindo a tela inteira e, para ele não roubar cliques enquanto está transparente, defina o Mouse → Filter como Ignore. Garanta também que o CanvasLayer da transição tenha um Layer alto, para ficar acima do HUD.

Remapeamento: os controles são do jogador

No Módulo 02 você definiu ações no InputMap (move_left, jump…). Aquilo era fixo no editor. Agora vamos deixar o jogador reconfigurar em tempo de execução — a mesma InputMap, mas alterada por código.

A ideia: um botão "espera" a próxima tecla, captura o InputEventKey, apaga os eventos antigos da ação e adiciona o novo.

RemapButton.cs C# 
using Godot;

public partial class RemapButton : Button
{
    [Export] public string Action = "jump";
    private bool _waiting;

    public override void _Ready() => UpdateLabel();

    // Signal "pressed" do próprio botão
    private void OnPressed()
    {
        _waiting = true;
        Text = "Pressione uma tecla...";
    }

    public override void _Input(InputEvent @event)
    {
        if (!_waiting || @event is not InputEventKey { Pressed: true } key)
            return;

        InputMap.ActionEraseEvents(Action);   // remove o mapeamento antigo
        InputMap.ActionAddEvent(Action, key);  // grava a tecla nova
        _waiting = false;
        UpdateLabel();
        GetViewport().SetInputAsHandled();     // não deixa a tecla "vazar" pro jogo
    }

    private void UpdateLabel()
    {
        var events = InputMap.ActionGetEvents(Action);
        Text = events.Count > 0 ? events[0].AsText() : "—";
    }
}
Persistir o remapeamento

Mudanças no InputMap valem só para a sessão. Para sobreviverem, salve os eventos de cada ação no settings.cfg (Aula 6.2) e reaplique no boot — o mesmo padrão do volume e da tela cheia.

Fade entre cenas e tela de controles

Vamos dar fade a todas as trocas de cena e criar uma tela onde o jogador remapeia uma ação.

1
Monte o autoload de transição

Nova cena com CanvasLayer (SceneTransition) contendo um ColorRect preto chamado Fade, cobrindo a tela (anchors Full Rect), com Mouse → Filter = Ignore. Anexe SceneTransition.cs e registre em Autoload.

2
Troque as chamadas de cena

Onde havia GetTree().ChangeSceneToFile(...) (menu, game over, pause), passe a chamar SceneTransition.Instance.ChangeScene(...). Rode e sinta o fade em cada transição.

3
Crie a tela de Controles

Nova cena Control (Controls) com um RemapButton por ação (ex.: Pular, Esquerda, Direita). Ligue-a a partir das Opções. Salve em res://Scenes/UI/Controls.tscn.

4
Configure cada botão

Em cada RemapButton, defina a propriedade Action no Inspector (jump, move_left…) e conecte o pressed ao OnPressed.

5
Teste o remapeamento

Rode, abra Controles, clique num botão, pressione uma tecla nova e volte ao jogo: a ação deve responder à tecla remapeada.

6
Persista (opcional agora)

Salve os eventos remapeados no settings.cfg e reaplique no autoload Settings, para o mapeamento sobreviver ao fechar o jogo.

Ponto de verificação

Polimento pronto quando: (1) toda troca de cena tem fade, (2) o overlay não rouba cliques quando invisível, (3) remapear uma ação muda de fato o controle no jogo.

Botão "Restaurar padrões" Aula 6.3 · InputMap
Médio

Quem remapeia às vezes se enrola — todo menu de controles precisa de um "voltar ao original". Adicione um botão que restaura o mapeamento padrão do projeto.

  • 1
    Adicione um botão "Restaurar padrões" na tela de Controles
  • 2
    Ao clicar, recarregue o mapeamento original com InputMap.LoadFromProjectSettings()
  • 3
    Atualize o texto de todos os RemapButton para refletir as teclas restauradas
  • 4
    Apague (ou sobrescreva) o mapeamento salvo no settings.cfg
  • 5
    Teste: remapeie, restaure, e confirme que as teclas voltaram ao original — inclusive após reabrir o jogo

InputMap.LoadFromProjectSettings() descarta as alterações de runtime e recarrega exatamente o que está no Project Settings → Input Map — o "reset" pronto de fábrica.

Depois de restaurar, chame o UpdateLabel() de cada botão (ou emita um signal que todos escutem) para os textos não ficarem mostrando a tecla antiga.
