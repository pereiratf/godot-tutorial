Módulo 01 · Aula 1.1

Godot: licença, download e configuração

Do zero ao primeiro projeto rodando — instalação do Godot .NET, configuração do VSCode e criação do projeto base do curso.

~30 minutos Instalação + configuração

Por que Godot?

O Godot é uma engine open source com licença MIT: você pode usar comercialmente, distribuir modificações e manter 100% dos direitos sobre o que cria — sem royalties nem taxas de publicação. A engine inteira, incluindo o editor, está disponível no GitHub.

Godot 4 (MIT)
  • Gratuito, sem royalties, código aberto
  • Você detém 100% do jogo produzido
  • Editor incluído — sem assinaturas
  • GDScript e C# como linguagens principais
Alternativas comuns
  • Unity: modelo de royalties em versões recentes
  • Unreal: royalty de 5% após USD 1M de receita
  • GameMaker: assinatura para publicação multiplataforma
  • Curva inicial maior, ecossistema mais pesado

Por que C# e não GDScript?

O Godot suporta duas linguagens principais: GDScript (própria da engine, sintaxe próxima de Python) e C# (via .NET). Este curso usa C# por três razões:

  • Tipagem estática — erros aparecem em tempo de compilação, não de execução
  • Integração com VSCode: autocomplete, go-to-definition e refatoração robustos
  • Ecossistema .NET: convenções e padrões transferíveis para outros projetos
GDScript não é inferior

GDScript tem integração mais profunda com o editor Godot e é mais rápido para prototipar. Se você já conhece Python, pode ser mais produtivo nele. C# é a escolha deste curso por ser mais próximo de linguagens usadas em contextos profissionais.

Configurar o Godot para abrir o VSCode

Por padrão o Godot abre scripts no seu editor interno. Para redirecionar ao VSCode: Editor → Editor Settings → Dotnet → Editor → External Editor → Visual Studio Code. Após salvar, clicar em qualquer script .cs abre o arquivo no VSCode automaticamente.

Como verificar que a integração funciona

Crie um script C# no Godot e abra-o. No VSCode, ao digitar GetNode, o autocomplete deve sugerir a assinatura do método com os tipos corretos do Godot. Se não aparecer, feche e reabra o VSCode com a pasta do projeto aberta — o arquivo .csproj precisa estar visível na raiz.

Configurar o ambiente do zero

Siga os passos abaixo em ordem. Ao final você terá o projeto PlataformaDemo criado e a integração VSCode funcionando.

1
Instale o Godot 4 .NET

Acesse godotengine.org → Download. Baixe a versão Godot Engine - .NET para o seu sistema operacional. Extraia o zip e execute o executável — não há instalador, o Godot é portátil.

2
Instale o .NET SDK 8 ou superior

Acesse dot.net e baixe o .NET SDK (não o Runtime — precisa ser o SDK completo). Após instalar, confirme no terminal: dotnet --version deve retornar 8.x.x ou superior.

3
Instale as extensões no VSCode

Na aba Extensions do VSCode, instale: C# Dev Kit (publicador: Microsoft) e Godot Tools (publicador: geequlim). Reinicie o VSCode após instalar.

4
Configure o editor externo no Godot

No Godot: Editor → Editor Settings. No painel esquerdo navegue até Dotnet → Editor. Em External Editor, selecione Visual Studio Code e feche as configurações.

5
Crie o projeto PlataformaDemo

No Godot, clique em Novo Projeto. Nome: PlataformaDemo. Renderizador: Forward+. Marque .NET antes de criar. Clique em Criar e Editar.

6
Confirme a integração

Crie uma cena com um Node como raiz. Clique no ícone de script → Criar. O VSCode deve abrir o arquivo .cs. Ao digitar dentro de _Ready(), você deve ver sugestões de métodos do Godot.

Se o autocomplete não aparecer

O arquivo .csproj é gerado pelo Godot quando você cria o primeiro script C#. Se o autocomplete não aparecer logo após criar o script, feche e reabra o VSCode apontando para a pasta do projeto.

Módulo 01 · Aula 1.2

A lógica de nodes e cenas

Entender a estrutura fundamental do Godot antes de escrever uma linha de código. O maior choque de quem chega do zero numa engine.

~30 minutos Conceitual

O que é um node?

Se você já trabalhou com POO, sua intuição inicial vai ser: "node é uma classe, cena é um objeto". Isso está parcialmente certo — mas na prática o Godot inverte o que você está acostumado a fazer.

Em linguagens tradicionais, você escreve uma classe Player que herda de Character, instancia ela no main() e chama métodos. No Godot, você não escreve um main(). Você monta uma árvore de nodes — e a engine executa essa árvore pra você.

Analogia

Pense num node como um bloco LEGO especializado. Cada tipo de node já tem um comportamento embutido: um Sprite2D sabe como desenhar uma textura, um CollisionShape2D sabe como ocupar espaço físico, um AudioStreamPlayer sabe como tocar áudio. Você combina blocos, não reimplementa tudo do zero.

A árvore de cenas

Nodes se organizam em hierarquia pai → filho. Essa hierarquia é a SceneTree — a estrutura central que a engine lê a cada frame. Quando um node pai se move, todos os filhos acompanham. Quando o pai é removido, os filhos vão junto.

Exemplo: cena de um inimigo patrulheiro
Enemy [CharacterBody2D] ← Enemy.cs ├── Sprite2D [Sprite2D] ├── CollisionShape2D [CollisionShape2D] ├── DetectionArea [Area2D] │ └── CollisionShape2D [CollisionShape2D] └── PatrolRayCast [RayCast2D]

Cada node dessa árvore é responsável por uma coisa só. Você não escreve código de detecção dentro do script de movimento — você adiciona um node Area2D que já sabe fazer isso, e reage ao que ele emite.

Classe vs. instância vs. cena

No Godot, uma cena é um arquivo .tscn que descreve uma árvore de nodes com suas propriedades configuradas. É como um prefab: uma cena de Coin pode ser instanciada dezenas de vezes no mapa. Cada instância é independente, mas todas partem do mesmo template.

OOP tradicional
  • Você define class Player
  • Herança para reutilizar comportamento
  • Você instancia no main()
  • Comunicação por chamada direta de método
Godot (nodes)
  • Você cria uma cena com nodes
  • Composição de nodes para reutilizar
  • Engine instancia via SceneTree
  • Comunicação preferencialmente por signals
Para quem vem de Unity

A diferença principal: no Unity, um GameObject é quase vazio e você adiciona Components. No Godot, cada node já é um tipo específico com comportamento. A hierarquia de herança fica mais simples, e a composição fica mais explícita na SceneTree.

Scripts são anexados a nodes

Um script C# no Godot não é uma classe independente que você instancia manualmente. Ele é anexado a um node e estende o comportamento desse node. Quando o engine processa aquele node, ele executa seu script automaticamente.

Player.cs C# 
using Godot;

// Este script estende CharacterBody2D —
// ele só pode ser anexado a um node desse tipo.
public partial class Player : CharacterBody2D
{
    // [Export] expõe a variável no Inspector do editor
    [Export] public float Speed = 200f;

    // Chamado uma vez quando o node entra na SceneTree
    public override void _Ready()
    {
        GD.Print("Player pronto!");
    }

    // Chamado a cada frame de física (~60x por segundo)
    public override void _PhysicsProcess(double delta)
    {
        // Lógica de movimento aqui
    }
}

Repare que você não instancia Player manualmente. Você anexa esse script ao node Player na cena, e a engine cuida do ciclo de vida.

Ponto-chave

O método _Ready() é o seu "construtor seguro" — quando ele é chamado, todos os filhos do node já existem e podem ser acessados. Já o construtor padrão do C# (Player()) é chamado antes disso e não deve ser usado para lógica de jogo.

O loop principal: o que acontece a cada frame

Até aqui você viu a estrutura — nodes, cenas, scripts. Mas o que faz isso rodar é a engine repetindo um ciclo várias vezes por segundo, o game loop. Entender a ordem desse ciclo evita boa parte dos bugs de inicialização e de timing que você vai encontrar mais adiante.

Do F5 ao primeiro frame
1
Godot carrega a cena principal

Lê o project.godot, encontra a cena marcada como principal e instancia toda a árvore de nodes descrita nela.

2
_EnterTree() — de cima para baixo

Conforme cada node é adicionado à SceneTree, ele recebe esse callback. O pai entra primeiro, depois os filhos, na ordem em que aparecem na árvore.

3
_Ready() — de baixo para cima

Na ordem inversa do passo anterior: um node só recebe _Ready() depois que todos os seus filhos já receberam o deles. É por isso que GetNode() dentro de _Ready() é seguro.

4
Loop principal — repete a cada frame

A partir daqui a engine entra em loop: processa input, roda física, roda a lógica de jogo e desenha a tela. Esse ciclo só para quando o jogo é fechado.

Dentro de cada volta do loop, dois callbacks competem por atenção — e a diferença entre eles é uma das maiores fontes de bugs em quem está começando:

_PhysicsProcess(delta)
  • Taxa fixa: 60 vezes por segundo por padrão
  • delta é sempre o mesmo valor (≈0.0166s)
  • Pode rodar 0, 1 ou várias vezes por frame renderizado
  • Use para: movimento, colisão, física
_Process(delta)
  • Roda exatamente uma vez por frame renderizado
  • delta varia com a taxa de quadros atual
  • Não é sincronizado com a física
  • Use para: animação, UI, lógica que não depende de física
Por que multiplicar por delta?

Sem delta, o código Position += new Vector2(Speed, 0) move o personagem Speed pixels por frame. Em uma máquina rodando a 120 FPS ele anda o dobro do que em outra rodando a 60 FPS — o jogo fica mais rápido em hardware melhor. Multiplicando por delta você define a velocidade em pixels por segundo: a engine escala automaticamente para quantos frames aconteceram naquele intervalo. Em _PhysicsProcess o delta é quase constante (taxa fixa), mas em _Process é essencial para comportamento consistente entre máquinas.

E quando um node é removido?

Chamar Free() no meio de um _PhysicsProcess() pode quebrar a iteração da engine sobre a árvore. Por isso o padrão é QueueFree(): marca o node para ser removido com segurança no fim do frame atual, em vez de destruí-lo instantaneamente.

Explorando a SceneTree na prática

Antes de criar seu projeto completo, faça este exercício para internalizar a estrutura de nodes.

Pré-requisito

Godot 4 instalado com suporte a .NET habilitado. Crie um projeto 2D vazio chamado PlataformaDemo antes de começar.

1
Defina o node raiz da cena

Um projeto recém-criado abre direto com a viewport vazia mostrando os botões 2D Scene, 3D Scene, User Interface e Other Node — não existe nenhuma cena ainda, então não precisa ir a um menu. Clique em 2D Scene para criar um Node2D como raiz (isso é o mesmo que Cena → Nova Cena, só que o Godot já deixa esse atalho na tela quando não há nenhuma cena aberta). Salve como res://scenes/TestScene.tscn.

2
Adicione um node filho

Com o Node2D selecionado na SceneTree, clique no ícone "+" para adicionar filho. Adicione um Label. Observe como ele aparece indentado na árvore abaixo do Node2D.

↑ topo do painel Scene
3
Anexe um script ao Node2D raiz

Selecione o Node2D raiz → clique no ícone de script → Criar. Godot gera um arquivo .cs automaticamente e abre o editor.

↑ mesmo painel, ícone de script
4
Acesse um nó filho por código

No _Ready(), use GetNode<Label>("Label") para pegar a referência ao Label filho e altere o texto.

5
Rode e observe

Pressione F5 para rodar o projeto. Veja o output no painel inferior. Mova nodes na SceneTree e observe como as posições mudam no viewport.

TestScene.cs C# 
using Godot;

public partial class TestScene : Node2D
{
    public override void _Ready()
    {
        // Acessa o Label pelo nome que aparece na SceneTree
        var label = GetNode<Label>("Label");
        label.Text = "Meu primeiro node!";

        GD.Print("Filhos desta cena: " + GetChildCount());
    }
}
Experimento extra

Renomeie o node Label na SceneTree para TituloLabel. O código vai quebrar — você precisará atualizar a string em GetNode. Essa fragilidade existe e há formas melhores de referenciar nodes (como [Export] ou %NodeUnico), que veremos na aula 2.1.

Restrição do desafio

Não copie a estrutura da árvore do diagrama visto na aula. Justifique no comentário do script por que escolheu cada node filho. Se sua cena tiver apenas o node raiz, tudo bem — explique por quê.

Um coletável 2D geralmente precisa de: algo que detecte quando o player passa por cima (um node de área, não de física sólida) e algo visual. O pack Sunny Land tem sprites de gem — importe-os em res://assets/ e use um Sprite2D com o frame idle da gem.

A pergunta certa é: "minha gem precisa ter colisão física sólida, ou só precisa saber se algo entrou na área dela?" Isso determina o tipo do node raiz. A lógica de coleta real — detectar o player e remover a gem da cena — fica para um desafio futuro.

SceneTree — a árvore de nodes

Painel superior-esquerdo. É onde você monta a hierarquia de nodes da cena aberta. Clicar num node o seleciona no viewport e abre suas propriedades no Inspector.

Inspector — propriedades do node selecionado

Painel direito. Mostra todas as propriedades do node — incluindo as que você decorou com [Export] no script. Editar aqui é equivalente a editar no código, mas persiste na cena salva.

Dica importante

Variáveis com [Export] podem ter valores diferentes por instância. Você define o default no código, mas pode sobrescrever no Inspector pra cada inimigo ou plataforma individualmente — sem tocar no script.

FileSystem — seus arquivos de projeto

Painel inferior-esquerdo. Mostra a estrutura de pastas dentro de res:// — o caminho raiz do seu projeto. Cenas são .tscn, scripts C# são .cs, assets ficam em subpastas que você organiza.

Viewport — onde o jogo aparece

A área central. No modo 2D você movimenta, escala e rotaciona nodes visualmente. O Godot usa Y crescente para baixo — o (0,0) fica no canto superior-esquerdo por padrão.

Abas de modo: 2D, 3D, Script, AssetLib

Bem acima do Viewport existem quatro abas que trocam completamente o que aparece na área central. É fácil confundir isso com os painéis fixos vistos acima — eles são independentes e sempre estão lá, não importa em qual aba você esteja.

A aba 2D é onde você monta cenas visualmente — é a que vamos usar quase sempre neste tutorial. A aba Script abre o editor de código; é pra lá que o Godot te leva automaticamente quando você cria ou dá duplo-clique num script C#. 3D e AssetLib não aparecem muito num projeto 2D.

1
Novo projeto com .NET

No launcher do Godot: Novo Projeto → Renderer: Compatibility → Linguagem: C# (.NET). Nomeie PlataformaTutorial e escolha uma pasta.

2
Crie a estrutura de pastas

No FileSystem, clique-direito → Nova Pasta para criar scenes/, assets/, autoload/. Dentro de scenes/, crie world/ e entities/.

3
Crie a cena do mundo

Como o projeto acabou de ser criado, a viewport ainda está esperando você escolher um node raiz — clique em 2D Scene para criar um Node2D (se essa tela não aparecer mais, use Cena → Nova Cena). Salve em res://scenes/world/Level01.tscn. Este será o ponto de entrada do jogo.
